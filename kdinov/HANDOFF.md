# 정책 아이디어 신규성 검증 시스템 — 인계 문서

작성 2026-07-26 · 코드베이스 `kdinov/` · 버전 0.2.0

**이 문서는 배경·설계 근거·실패 이력을 담은 맥락 문서다.**
작업 지시와 수용 기준은 `AGENTS.md` 에 있다. Codex·Cowork 등 에이전트로
작업할 때는 `AGENTS.md` 를 먼저 읽고, 규칙을 고치기 전에 이 문서 5절
(오판정 이력)로 돌아올 것.

대화 재조회 없이 읽어도 되도록 확인된 사실, 설계 근거, 실패 이력, 미해결
과제를 모두 담았다.

| 문서 | 역할 |
|---|---|
| `AGENTS.md` | 에이전트 진입점. 검증 명령, 손대지 말 것, 작업 목록과 수용 기준 |
| `HANDOFF.md` | 이 문서. 확인된 사실, 설계 근거, 오판정 이력, 사례 2건 |

## 1. 목적

정책 아이디어가 실제로 새로운지 판정한다. 사람이 하던 절차 — 검색하고,
제목이 비슷한지 보고, 본문을 읽어보는 — 를 기계화하되 **"없다"는 결론이
언제 신뢰할 수 있는가**를 명시적으로 통제한다.

검증 대상 예시: `중소기업에 AI 교육을 무상으로 지원`, `예술가에게 기본소득`

핵심 문제의식은 두 가지다.

첫째, 자연어 문장을 검색창에 그대로 넣으면 0건이 나온다. 그리고 0건은
'신규'가 아니라 '검색 실패'일 수 있다. 이 둘을 구별하지 못하면 시스템은
쓸모가 없다.

둘째, "있다/없다"의 이진 판정은 아무 판단도 못 만든다. 같은 정책이
이미 집행 중인 것과, 효과분석 근거만 축적된 것은 완전히 다른 상황이다.

## 2. 확인된 사실 — 재조사 불필요

이 절의 내용은 실제로 접속해 확인했다. 다시 파헤치지 말 것.

### 2.1 KDI Open API 스펙

```
https://www.kdi.re.kr/KDIOpenAPI?type=json&apiKey={KEY}&cd={CD}
                                &srhKey={ALL|TITLE|NAME|CONTENT}&srhValue={용어}
```

- 키 발급: `https://www.kdi.re.kr/share/openAPI` 이메일 인증 방식.
  신청 → 확인 → 인증키 이메일 발송. **아직 발급받지 않았다.**
- `type`: xml | json (필수)
- `cd` (필수): `A` 기본연구보고서 · `B` 현안자료 · `C` KDI 경제전망 ·
  `D` KDI 경제동향 · `E` 학술지 · `F` 영상보고서
- `srhKey` 기본값 `ALL`, `srhValue`는 **선택**. 따라서 `srhValue` 없이
  호출하면 해당 `cd` 전체 목록이 올 것으로 기대된다 (미검증, 아래 3.2 참조).
- 응답 필드: `TOTAL_COUNT`, `ARCHIVE[]` 안에
  `PUB_NM_KORN` `PUB_NM_ENG` `PUB_CD` `PUB_CD_NM` `SERIES_NO_KORN`
  `SERIES_NM_KORN` `MAIN_AUT_NM` `SUB_AUT_NM` `CO_AUT_NM`
  **`PUB_CN`(목차)** **`SUMM_KORN`(국문요약)** `SUMM_ENG` `ISSU_DT`
  `ISSU_OFFICE_KORN` `PUB_LANG` `PUB_TYPE` `PUB_KEYWORD` `TOPIC_ARR`
  `DETAIL_PAGE`
- `cd=F`(영상)만 필드 체계가 다르다: `MOV_NM` `MOV_CN` `LINK_URL` 등.

**`PUB_CN`(목차)과 `SUMM_KORN`(요약)이 함께 온다는 점이 이 시스템의 토대다.**
제목만으로는 판정이 거칠고 PDF 본문은 비싸다. 목차가 정확히 그 중간층이며,
절 제목 수준의 정보가 정책 벡터 방향까지 드러낸다 (5.3 참조).

### 2.2 KDI 코퍼스 규모와 분류

- 연구보고서+정책연구시리즈: **1,383건** (2026-07 기준). 미러링이 싸다.
- 연구주제 코드: `A` 거시 · `B` 금융 · `C` 법경제 · `D` 규제 · `E` 노동 ·
  `F` 교육 · `G` 산업 · `H` 국제경제 · `I` 재정 · `J` 복지 · `K` 북한경제 ·
  `L` 공공투자 · `M` 국토인프라 · `N` 국제개발협력 · `O` 경제교육 ·
  `P` 경제정보
- **문화·예술 분류가 없다.** 구조적 한계이며 6.2에서 실제로 문제가 됐다.
- `reportList` 페이지는 목록 10건의 국문요약 전문을 모달에 담아 서버사이드
  렌더링한다. 그러나 페이징이 `javascript:;` 이므로 URL로 넘길 수 없다.
- `reportView?pub_no={N}` 상세 페이지에는 국문요약·영문요약·절 단위 목차·
  주제태그·저자·발간일이 모두 있다. 인증키 없이 개별 문헌 정독이 가능하다.

### 2.3 검증 계층 분리 — 가장 중요한 방법론적 사실

**KDI 본체만으로 신규성을 판정하면 반드시 과대추정한다.** KDI는 정책을
만드는 곳이 아니라 평가하는 곳이다.

| 층위 | 소스 | 답하는 질문 | 접근 |
|---|---|---|---|
| 담론·평가 | KDI Open API | 학술적으로 논의·평가됐나 | API |
| **정책 실재** | eiec.kdi.re.kr 경제정책정보 | 실제로 존재·추진 중인가 | 공개 API 없음 |
| 발주 이력 | PRISM(prism.go.kr), 중기연구원, KISDI, 국회입법조사처 | 이미 용역이 나갔나 | 공개 API 없음 |

eiec 경제정책정보 DB가 사실상 진짜 검증대다. 부처 자료와 타 국책연구원
보고서를 집적하고 있다. 두 사례 모두 결정적 증거는 KDI 본체가 아니라
여기서 나왔다.

### 2.4 도구 권한 경계 (대화형 환경에서 확인)

| 경로 | kdi.re.kr | 비고 |
|---|---|---|
| `web_search` | ○ | 검색엔진 색인 경유 |
| `web_fetch` | △ | **검색 결과로 나온 URL만.** 주소를 조립하면 `PERMISSIONS_ERROR` |
| 스크립트 실행 환경 | ✗ | 완전 차단. `mirror`/`probe` 실행 검증 불가 원인 |

`topicList?cd=G`는 앞서 가져온 페이지 본문에 링크로 있었는데도 거부됐다.
반면 `reportView?pub_no=17243`은 검색 결과로 올라온 주소라서 성공했다.
**결론: 목록 훑기와 페이징은 불가. 검색으로 걸린 개별 문헌 정독만 가능.**

Cowork 환경의 네트워크 정책은 다를 수 있으니 첫 세션에서 재확인할 것.

### 3.2 검증 상태 — 무엇이 확인됐고 무엇이 안 됐나

| 항목 | 상태 |
|---|---|
| 축 매칭 · 공기 판정 · 방향성 규칙 · 역할 판정 | ○ 실제 문헌으로 검증, 테스트 고정 |
| 형태소 분석기 부재 시 판정 동일성 | ○ `KDINOV_NO_KIWI=1` 로 24건 통과, 판정 결과 일치 |
| `parse_archive` 스키마 처리 | △ 문서 기준 작성, 합성 페이로드로만 검증 |
| `mirror` / `probe` 실 엔드포인트 | ✗ **미검증.** 네트워크 차단 |
| 전체목록 호출 (`srhValue` 생략) | ✗ **미검증.** 막혀 있을 수 있음 |

**첫 작업은 `probe`다** (`AGENTS.md` 작업 2). 인증키 미발급 상태로 차단됨.

```bash
export KDI_API_KEY=...
python -m kdinov probe --cd A
```

`TOTAL_COUNT`가 1,300대로 나오고 `record keys`에 `PUB_NM_KORN`,
`SUMM_KORN`, `PUB_CN`이 있으면 정상. `ARCHIVE`가 짧게 잘려 오면 전체목록
호출이 막힌 것이므로 `mirror --terms` 대체 경로를 쓰되, 그 경로는 재현율이
구성적으로 보장되지 않으므로 `known_positives` 통제를 반드시 통과해야 한다.

## 4. 설계 결정과 근거

### 4.1 검색을 위탁하지 않는다 — 코퍼스 미러링

**초기 버전은 KDI 검색엔진에 질의를 던졌다. 이것이 근본 결함이었다.**
재현율을 통제할 수 없기 때문이다. 0건이 나왔을 때 그것이 신규인지 그들의
토크나이저가 검색어를 못 쪼갠 것인지 알 방법이 없다.

지금은 코퍼스를 로컬 SQLite로 미러링하고 매칭을 직접 수행한다. 얻는 것:

- 재현율이 구성적으로 보장된다
- 채점 규칙을 고쳐도 재수집이 필요 없다 → 반복 실험 가능
- 검색 랭킹 변동에 흔들리지 않는다 → 결과 재현 가능

### 4.2 축 분해

정책 아이디어는 항상 **대상 × 수단 × 영역**의 조합이고, 여기에
**재원 · 전달체계**가 딸린다. 축별로 `exact`/`syn`/`broad`를 구분해 선언하고
매칭 가중치를 각각 1.0 / 0.75 / 0.45로 감쇠시킨다.

검색은 축별 단일어로 넓게 긁고 교집합은 로컬에서 만든다. 검색엔진에
논리곱을 맡기지 않는다.

**축 이름 `대상`·`수단`·`영역`은 고정이다.** 방향성 규칙이 이 이름에
결합되어 있다.

### 4.3 필드별 증거 가중치

```
title 3.0 > keyword 2.5 > toc 2.0 > summary 1.0
```

제목에 걸린 것과 요약 끝에 스친 것은 같은 증거가 아니다.

### 4.4 2차원 판정

한 축으로는 못 쓴다는 것이 1차 실행에서 드러났다. "수단축이 비었다"는
사실만으로는 그 문헌이 경합자인지 인용할 근거인지 알 수 없다.

**code — 중첩의 정도**

| code | 의미 |
|---|---|
| N0 | 3축이 한 단위에서 일치. 신규 아님 |
| N1 | 축 하나가 상이하거나 3축이 흩어져 있음 |
| N2 | 축 하나만 강하게 겹침 |
| N3 | 영역만 중첩 |
| N4 | 무관 |

**role — 어떻게 쓸 것인가**

| role | 의미 | 대응 |
|---|---|---|
| 실행 | 법령·시행령·보도자료·업무계획. 이미 제도화 | 신규성의 직접 반증. 폐기 또는 재설계 |
| 경합 | 같은 수단을 이미 제안 | 차별화 논증 필요 |
| 근거 | 효과분석·현황진단만, 수단 제안 없음 | **인용해서 정당화에 쓴다. 노려야 할 자리** |
| 선례 | 영역은 다르나 재원·전달체계 설계 참조 가능 | 파라미터 벤치마크 |
| 무관 | | |

`실행`을 별도 등급으로 분리한 것이 중요하다. 연구문헌은 '논의'지만
시행령은 '집행'이다. 신규성 검증에서 이 둘은 같은 무게가 아니다.
판정 우선순위에서 `실행`이 모든 것을 압도한다.

### 4.5 재현율 통제 — '없음' 결론의 유효조건

`known_positives`에 사람이 손으로 찾아 확인한 문헌을 적는다. 파이프라인이
이것을 **표면화하지 못하면 종합 판정은 `VOID`**가 되고 신규성을 주장할 수 없다.

두 단계를 모두 본다.

1. 코퍼스에 실제로 들어와 있나 (미러링 검증)
2. N4로 강등되지 않고 후보 목록에 남았나 (채점 규칙 검증)

코퍼스에 있는데 채점이 N4로 떨어뜨리면 사람 눈에 안 보이므로 재현 실패와
다를 바 없다. 이 케이스는 `test_recall_catches_scoring_suppression`으로
고정해 뒀다.

## 5. 실행 중 발견한 오판정 4건과 수정

**규칙을 고칠 때 이 절을 먼저 읽을 것.** 각 항목은 실제로 오판정이 났던
지점이고 모두 회귀 테스트로 고정되어 있다. 테스트가 깨지면 고쳤던 오탐이
되살아난 것이다.

### 5.1 목차가 통째로 한 문장 취급됨 — 최악의 오탐

KDI 목차는 `제1장`이 아니라 `1. 2. 3.`으로 한 줄에 붙어 온다. 분할하지
않으면 목차 전체가 하나의 공기 창이 되어 **3축 공기가 무조건 성립한다.**

수정: `score.py::_TOC_SPLIT` — 개행, `·`, `;`, `/`, `제N장/절`,
아라비아 숫자 `N.`, 로마자, `가.나.다.` 를 모두 구분자로 처리.
테스트 `test_toc_split_on_arabic_numbering`.

### 5.2 키워드 태그 뭉치를 공기 창으로 사용

'중소기업'과 '인공지능'이 같은 색인 태그 목록에 있다는 사실은 두 개념이
연결됐다는 증거가 못 된다.

수정: `windows()`에서 `keyword` 필드 제외. 단 `coverage()`에서는 계속 쓴다
(축 존재 증거로는 유효하므로). 테스트
`test_keyword_bag_is_not_a_cooccurrence_window`.

### 5.3 형태소 분해로 방향성 규칙이 발화하지 못함

kiwipiepy는 `인공지능`을 `인공`+`지능`으로 쪼갠다. 토큰 단위로 비교하면
규칙이 매칭되지 않는다.

수정: 방향성 규칙을 **원문 표면형 정규식**으로 전환. 형태소 분석기는
문장 분할에만 쓴다. 테스트 `test_direction_survives_morpheme_split`.

### 5.4 집행문서를 '근거'로 분류

「AI기본법 시행령 개정안 입법예고」가 role=근거로 나왔다. 시행령은 근거가
아니라 반증이다.

수정: `verdict.py::ENACTED_KINDS` 에 정책자료·법령·시행령·입법예고·
보도자료·고시·훈령·업무계획·대책을 넣고 `실행` 등급 신설. 종합 판정에서
경합보다 우선. 테스트 `test_enacted_document_outranks_evidence`.

### 5.5 방향성을 창 하나로만 판정 (5.3과 별개)

제목에는 단서가 없고 목차나 요약의 특정 문장에만 역전 신호가 있는 경우가
흔하다. 「AI 기반 정부 지원 통합체계 구축방안」이 이 때문에 `unclear`로

수정: `direction_agg()` 신설. 상위 5개 창을 모두 보고, 역전 신호는 하나만
있어도 진단적이므로 우선 채택.

## 6. 방향성 판정 — 오탐의 최대 원인

축이 셋 다 걸려도 정책의 화살표가 반대일 수 있다.

> `중소기업 지원정책에 AI를 적용` vs `중소기업에 AI 교육을 지원`

대상·수단·영역이 모두 일치하지만 전자는 정부가 AI를 쓰는 이야기고 후자는
중소기업이 AI를 배우는 이야기다. 이 구별이 없으면 시스템은 무의미하다.

| 규칙 | 패턴 | 판정 |
|---|---|---|
| B | 영역어 + 목적격 + 운용동사 (`AI 기술을 적용`) | 역전 |
| B2 | 영역어 + 행정작용 수식 (`AI 기반 정부 지원`) | 역전 |
| C | 대상어 + 정책/사업 (`중소기업 지원사업`) | 역전 |
| A | 영역어 + 수단어 복합 수식 (`AI 교육`) | 정렬 |
| D | 3축 + 이전동사 공기 | 정렬 |

역전 판정 시 점수에 0.75 페널티를 주고 code를 N3으로 강등한다.
`unclear`는 0.15 페널티에 사람 확인 플래그.

B를 A보다 먼저 본다. `AI 기술을 적용`에서 `기술`이 수단 동의어로 잡히면
A가 오발화하므로 역전 신호에 우선권을 준다.

**실물 검증:** 「AI 기반 정부 지원 통합체계 구축방안」(pub_no=17243) 상세
페이지의 실제 목차에 `제3장 제2절 중소기업 자금 지원사업에의 AI 기술 적용`이
있다. 절 제목 하나에 규칙 C(`중소기업 지원사업`)와 규칙 B(`AI 기술 적용`)가
동시에 발화한다. 합성 데이터로 잡아낸 역전을 실물이 확인했다.

## 9. 미해결 과제

작업별 수용 기준은 `AGENTS.md` 에 있다. 이 절은 각 과제의 **근거**를 남긴다.

### 작업 1 — 조건성 축 추가

8.2가 근거. 소득보장·현금이전 정책 전반에 재사용될 구조이므로 한 번
만들어둘 값이 있다.

설계 방향 제안:
- 4번째 축 `조건성`을 선택적으로 도입. 있으면 판정에 참여, 없으면 현행 동작.
- 하위 차원: 보편성(전수/선발/자산조사), 무조건성(무조건/활동요건/실업요건),
  주기(월/주/연N회/격년/일시), 현금성(현금/준현금/바우처/서비스).
- 차원별로 아이디어와 문헌의 값을 비교해 **거리**를 계산. 3축이 모두 겹쳐도
  조건성 거리가 크면 N0에서 N1으로 강등.
- `financing`/`delivery` 리스트를 이 축으로 승격하고 어휘를 차원별로 분류.

주의: 축 이름이 방향성 규칙에 하드코딩되어 있다(`domain_axis` 등 기본값).
축을 늘릴 때 `direction()` 시그니처를 확인할 것.

### 작업 2 — `probe`로 실 스키마 확정

3.2 참조. API 키 신청이 선행되어야 한다. 응답을 받으면
`sources.py::parse_archive`의 필드 후보 목록과 `mirror()`의 전체목록 가정을
확정하고, `test_parse_archive_*` 를 실제 페이로드 기반으로 교체할 것.

### 작업 7 — 문화·예술 분야 코퍼스 어댑터

8.3 참조. eiec 경제정책정보, KCTI, 예술경영지원센터에 공개 API가 없다.
현재는 `ingest --jsonl` 손수집이 유일한 경로다. HTML 스크레이퍼를 만들지,
손수집을 유지할지 판단이 필요하다. 손수집을 유지한다면 `external_*.jsonl`을
아이디어별로 축적해 자산화하는 편이 낫다.

### 작업 5 — `unclear` 방향성의 보조 판정

규칙 기반이라 재현율이 완전하지 않다. `unclear`로 빠진 건에 대해
근거 문장과 아이디어를 함께 넣어 방향을 물어보는 보조 판정을 붙일 수 있다.
단 규칙 판정을 대체하지 말고 `unclear`에만 적용할 것 — 재현 가능성을
잃지 않기 위해서다.

### 작업 6 — 동의어 확장 보조

**축 용어집을 사람이 만드는 것이 이 시스템의 실질적 상한이다.**
`중소기업` 동의어에 `영세사업자`를 넣지 않으면 그 문헌은 안 걸린다.
`known_positives` 통제가 이 실패를 잡아주지만 통제 자체도 손으로 찾은
것이라 완전하지 않다.

코퍼스에서 축 용어와 자주 공기하는 명사를 추출해 동의어 후보를 제안하는
보조 도구가 도움이 될 것이다. 사람이 승인하는 방식으로.

### 작업 3 — `broad` 매칭 오탐 점검
`지원`이 `수단.broad`에 있어 거의 모든 정책 문헌에 걸린다. 사례 1에서
「AI 기반 정부 지원」의 `수단@title`이 이것이었다. 가중치 0.45로 감쇠되지만
축 존재로 인정되는 것 자체가 문제일 수 있다.

### 작업 4 — 목차 분할 규칙 확충
미처리 형태: `①②③`, `Ⅰ Ⅱ Ⅲ`, `1-1`, `가) 나) 다)`.

### 미배정
- 판정 결과를 아이디어별로 누적해 이력을 남기는 기능. 같은 아이디어를

## 10. 이 시스템의 한계 — 명시적으로

판정을 최종 답으로 취급하면 안 된다. **검토 대상 목록**으로 봐야 한다.
그래서 보고서에 근거 문장을 항상 싣도록 설계했다. 사람이 뒤집을 수 있어야
하고, 그러려면 왜 그렇게 판정했는지가 눈앞에 있어야 한다.

세 가지 상한이 있다.

1. **축 용어집이 사람 손에 달려 있다** (9-5)
2. **방향성 규칙이 규칙 기반이다** — `unclear`는 사람이 봐야 한다
3. **코퍼스 커버리지가 분야마다 다르다** — KDI는 경제 분야에 강하고
   문화·예술에는 아예 없다 (8.3)

`known_positives` 통제는 1과 3을 부분적으로 잡아주는 장치다. 이것을
비워두고 돌리면 시스템의 신뢰성 주장 근거가 사라진다. 반드시 채울 것.
