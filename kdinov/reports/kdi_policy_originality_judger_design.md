# KDI 정책 데이터베이스 기반 아이디어 독창성 판단기 설명서

작성일: 2026-07-27

## 1. 목적

이 도구의 목적은 정책 아이디어가 기존 KDI 문헌에서 이미 많이 언급되었는지, 또는 기존 논의와 얼마나 다른지를 초벌로 판정하는 것이다.

핵심은 인공지능이 감으로 "새롭다"고 말하는 것이 아니다. 사용자가 제시한 정책 아이디어를 구조화하고, 실제 문헌 데이터베이스와 대조하여 어떤 문헌과 어떤 축에서 겹치는지 보여주는 것이다.

따라서 최종 목표는 다음과 같다.

```text
정책 아이디어 입력
  -> 대상/수단/영역 자동 분해
  -> KDI 문헌 DB 검색
  -> 중첩도 계산
  -> 독창성 초벌 판정
  -> 근거 문헌 표시
```

## 2. 현재 작동 방식

현재 웹 페이지는 실제 KDI 전체 DB가 아니라 데모 코퍼스를 사용하고 있다. 즉, 지금 단계의 결과는 공식 판단이 아니라 작동 구조를 확인하기 위한 예비 판정이다.

현재 흐름은 다음과 같다.

1. 사용자가 정책 아이디어 원문을 입력한다.
2. 시스템이 문장을 `대상`, `수단`, `영역`으로 자동 분해한다.
3. 각 축에서 직접어, 유사어, 넓은 관련어를 만든다.
4. 현재 연결된 문헌 코퍼스에서 제목, 키워드, 목차, 요약을 검색한다.
5. 세 축이 얼마나 겹치는지 계산한다.
6. 결과를 `N0~N4`로 표시한다.

현재 자동 분해는 외부 GPT API가 아니라 규칙 기반이다. 예를 들어 `오프그리드`, `생존 인프라`, `마이크로그리드`, `회복탄력성`, `공급망 단절` 같은 표현을 인식하여 축별 검색어 후보를 만든다.

## 3. 대상·수단·영역 분해

정책 아이디어는 보통 세 축으로 나누어 볼 수 있다.

| 축 | 의미 | 예시 |
|---|---|---|
| 대상 | 정책이 겨냥하는 사람, 조직, 지역, 산업, 인프라 | 중소기업, 예술인, 재난 취약지역, 필수 인프라 |
| 수단 | 정책이 사용하는 도구나 제도 | 교육, 바우처, 기본소득, 오프그리드 모듈, 공공조달 |
| 영역 | 정책이 속한 문제 분야 | AI, 문화예술, 재난안전, 경제안보, 기후위기 |

각 축은 다시 세 수준의 검색어로 나뉜다.

| 수준 | 의미 | 사용 방식 |
|---|---|---|
| exact | 직접 표현 | 가장 강한 중첩 증거 |
| syn | 유사 표현 | 같은 정책군일 가능성 |
| broad | 넓은 관련어 | 인접 문헌 탐색용 |

예를 들어 `분산형 생존 인프라`라는 정책 아이디어는 다음처럼 분해될 수 있다.

| 축 | 예시 검색어 |
|---|---|
| 대상 | 분산형 생존 인프라, 생존 인프라, 필수 인프라, 핵심기반시설 |
| 수단 | 오프그리드, 자립 모듈, 마이크로그리드, 분산에너지, 모듈 표준화 |
| 영역 | 극한 기후, 재난 대비, 회복탄력성, 경제안보, 공급망 단절 |

## 4. 문헌 검색 방식

문헌 검색은 단순 키워드 검색이 아니라 축별 중첩 검색이다.

문헌의 다음 필드를 확인한다.

- 제목
- 키워드
- 목차
- 요약
- 문헌 종류와 출처
- 발행일
- 상세 페이지 URL

같은 단어가 어디에서 발견되었는지에 따라 증거 강도가 달라진다.

| 위치 | 의미 | 가중치 |
|---|---|---|
| 제목 | 핵심 주제일 가능성이 높음 | 강함 |
| 키워드 | 주요 분류어일 가능성이 높음 | 중간 이상 |
| 목차 | 문헌 구조 안에서 다룸 | 중간 |
| 요약 | 관련 언급이 있음 | 약함 |

따라서 `오프그리드`가 제목에 들어간 문헌은 강한 증거이고, 요약에 한 번만 등장한 문헌은 약한 증거로 본다.

## 5. N0~N4 판정 체계

판정은 다음과 같이 해석한다.

| 등급 | 의미 | 독창성 해석 |
|---|---|---|
| N0 | 대상·수단·영역이 거의 그대로 겹침 | 독창성 낮음 |
| N1 | 세 축이 모두 겹치지만 완전 동일은 아님 | 강한 선행 논의 있음 |
| N2 | 두 축 정도가 강하게 겹침 | 부분 중첩 |
| N3 | 같은 영역의 인접 문헌만 있음 | 인접 논의 있음 |
| N4 | 현재 DB에서 중첩 문헌 없음 | 신규성 주장 가능, 단 DB 범위 확인 필요 |

`N4`는 "진짜로 세계 최초"라는 뜻이 아니다. 현재 검색한 DB 안에서 중첩 문헌이 발견되지 않았다는 뜻이다. 따라서 KDI 전체 DB가 연결되지 않은 상태에서는 반드시 "예비 판정"으로 읽어야 한다.

## 6. KDI API를 붙였을 때의 완성 구조

KDI Open API를 사용하면 KDI 웹사이트가 제공하는 문헌 메타데이터를 받아올 수 있다. KDI 공식 안내에 따르면 Open API는 KDI 웹사이트가 제공하는 다양한 메타데이터를 공개하는 서비스이며, API 신청, 신청자 확인, 승인 및 인증키 전송 절차를 거친다.

공식 안내 기준으로 제공 범주는 다음과 같다.

| 코드 | 범주 |
|---|---|
| A | 기본연구보고서 |
| B | 현안자료 |
| C | KDI 경제전망 |
| D | KDI 경제동향 |
| E | 학술지 |
| F | 영상보고서 |

응답 필드에는 보고서명, 보고서 구분, 저자, 목차, 요약, 발행일, 발행처, 키워드, 연구분야, 상세 페이지 등이 포함된다. 영상보고서의 경우 영상 제목, 스크립트, 링크, 등록일 등이 제공된다.

이 API를 붙이면 완성형 구조는 다음과 같다.

```text
KDI Open API
  -> 문헌 메타데이터 수집
  -> SQLite 저장
  -> 로컬 검색 인덱스 생성
  -> 정책 아이디어 자동 분해
  -> 대상/수단/영역 중첩 검색
  -> N0~N4 판정
  -> 근거 문헌 표시
```

## 7. 왜 실시간 검색이 아니라 SQLite 미러 DB인가

KDI 문헌은 양이 많고, API 접속이 제한되거나 차단될 가능성도 있다. 따라서 사용자가 아이디어를 입력할 때마다 KDI 서버에 실시간으로 검색 요청을 보내는 구조는 좋지 않다.

더 안전한 방식은 로컬 미러 DB 방식이다.

1. API 키로 문헌 메타데이터를 천천히 수집한다.
2. 요청 간격을 둔다.
3. 받은 결과를 SQLite에 저장한다.
4. 이후 모든 검색과 판정은 로컬 DB에서 수행한다.
5. 주기적으로 새 문헌만 갱신한다.

이 방식의 장점은 다음과 같다.

- KDI 서버에 반복 부담을 주지 않는다.
- 접속이 일시적으로 막혀도 로컬 검색은 계속 가능하다.
- 같은 아이디어를 반복 검증해도 결과가 재현된다.
- 판정 규칙을 고쳐도 문헌을 다시 받을 필요가 없다.
- 전체 문헌을 대상으로 빠르게 검색할 수 있다.

즉, 목표는 "KDI 검색창을 대신 누르는 도구"가 아니라 "KDI 문헌 메타데이터를 로컬 지식베이스로 만든 뒤 그 안에서 판정하는 도구"이다.

## 8. 구현 명령 예시

API 키가 준비되면 먼저 응답 구조를 확인한다.

```powershell
python -m kdinov probe --key <KDI_API_KEY> --cd A
```

정상적으로 `TOTAL_COUNT`와 문헌 목록이 내려오면 전체 범주를 미러링한다.

```powershell
python -m kdinov mirror --key <KDI_API_KEY> --db kdi.sqlite --full
```

그 다음 웹 페이지를 실제 DB 모드로 실행한다.

```powershell
python -m kdinov web --db kdi.sqlite
```

이때부터는 데모 코퍼스가 아니라 `kdi.sqlite`에 저장된 KDI 문헌 메타데이터를 검색한다.

## 9. API 기반 방식의 한계

KDI API만으로 가능한 것은 "전체 문헌 메타데이터 기반 검색"이다. 이것은 매우 유용하지만, "KDI 전체 PDF 본문을 완전히 읽는 것"과는 다르다.

따라서 다음 한계가 있다.

- API가 제공하지 않는 본문 세부 내용은 검색하지 못할 수 있다.
- 제목과 요약에는 없지만 PDF 본문에만 있는 개념은 놓칠 수 있다.
- KDI 외 기관의 정책자료, 보도자료, PRISM 과제, 국회·부처 자료는 별도 수집이 필요하다.
- API 응답 형식이나 제공 범위가 바뀌면 수집기를 조정해야 한다.

정확도를 높이려면 다음 자료를 추가하는 것이 좋다.

- KDI API 메타데이터
- 사용자가 확보한 KDI 문헌 목록 Excel
- EIEC 정책자료
- PRISM 연구보고서
- 부처 보도자료와 시행계획
- 필요한 경우 PDF 본문 텍스트 추출 자료

## 10. 최종 판단 원칙

이 시스템의 핵심 원칙은 다음이다.

> AI는 아이디어를 해석하고 검색어를 만든다.  
> 그러나 독창성 판단의 근거는 반드시 실제 문헌 DB에서 나온다.

따라서 좋은 결과는 단순히 "새롭다" 또는 "새롭지 않다"가 아니다. 좋은 결과는 다음을 함께 보여준다.

- 어떤 문헌이 걸렸는가
- 어떤 축에서 겹쳤는가
- 대상이 같은가
- 수단이 같은가
- 영역만 같은가
- 이미 시행된 정책인가, 연구 제안인가, 단순 근거 문헌인가
- 사용자의 아이디어가 기존 논의와 다른 지점은 어디인가

결론적으로, 이 판단기는 KDI API가 붙으면 다음 수준까지 완성할 수 있다.

| 수준 | 가능 여부 | 설명 |
|---|---|---|
| KDI 메타데이터 기반 전체 검색 | 가능 | API로 받은 제목·요약·목차·키워드 기반 |
| 로컬 SQLite 기반 반복 판정 | 가능 | 한 번 받은 뒤 로컬에서 검색 |
| KDI 전체 PDF 본문 기반 판정 | 추가 작업 필요 | PDF 수집·텍스트 추출 필요 |
| 공식 신규성 확정 판정 | 불가 | 전문가 검토와 정책 맥락 해석 필요 |

따라서 현실적인 완성 목표는 "KDI API 기반 문헌 메타데이터 전체를 로컬 DB로 만들고, 그 DB를 근거로 정책 아이디어의 독창성을 초벌 판정하는 웹 도구"이다.
