# K-Food 토픽·키워드 사전 — 설계와 근거

**KWCI L3(수용자 레이어) · 2026-08 · 358행 / 18개국 / 개념 20종**

---

## 1. 왜 K-Food가 먼저인가

기존 486행 사전에는 `KFOOD` 도메인 코드 자체가 없다.

```
도메인 코드 전체:  KPOP(396) · KVIDEO(54) · KTOURISM(36)
푸드 관련 흔적:    0행   (food·kimchi·ramen·김치·라면 전수 검색)
```

반면 L1에서 K-Food는 **동결 후보 928개 중 649개(70%)** 로 가장 두꺼운
도메인이다. 패널 3,150칸, 대표품목 30개, 2018→2024 지수 161.4.

지금 KWCI는 이렇게 어긋나 있다.

| 도메인 | L1 (수출) | L3 (신호) |
|---|---|---|
| K-Food | **649품목 · 3,150칸** | **없었음 → 358행** |
| K-Beauty | 22품목 · 1,575칸 | 없음 |
| K-Fashion | 257품목 · 3,150칸 | 없음 |
| K-Pop / K-Video / K-Tourism | 없음 | 396 / 54 / 178 |

**L1이 있는 도메인엔 L3가 없고, L3가 있는 도메인엔 L1이 없었다.** S3 회귀는
같은 도메인의 L1과 L3를 붙여야 돌아간다. 이 사전이 **처음으로 양쪽이 맞물리는
도메인**을 만든다. 그것도 가장 두꺼운 쪽에서.

---

## 2. 관광 사전과 다른 점 — 문법을 짜지 않는다

관광에서는 의도어 문법(항공권·숙박·비자·투어)을 내가 설계해야 했다. K-Food는
그럴 필요가 없다. **이미 동결된 대표품목 30개가 있다**(`item_master.lock.json`,
sha256 `27b210b3…`).

```
개념 = 동결된 top_items 30품목  →  소비자 검색어로 번역
질의 = 개념  ×  18개국 현지어
```

HS 190230을 `ramyeon`으로 옮기는 것은 **선정이 아니라 번역이다.** 무엇을
넣을지는 2026-07에 해시로 잠갔고, 여기서는 검색창의 말로 바꾸기만 한다.
사전이 품목 마스터에 종속되므로 선정 재량이 원천적으로 사라진다. 관광
사전보다 방법론적으로 강한 위치다.

`selection_basis`에 그 지위를 기록했다 — 품목 유래 행은
`FROZEN_ITEM_MASTER`, 도메인 수준·위약 행은 `RULE_GRAMMAR`.

---

## 3. 30품목이 30개념이 되지 않는 이유

두 가지 조정이 있고 **둘 다 규칙이다.**

### 3.1 소비자 검색어가 없는 품목은 뺀다

냉동 참치·가다랑어·고등어·게·이빨고기, 정제당, 조제분유. 원양어업과 B2B
원료라 애초에 검색 대상이 아니다. **이 판정은 검정 결과가 아니라 품목
성격에 의한 것이므로 사후 선택이 아니다.**

### 3.2 잔여분류(n.e.c.)는 뺀다

`210690`(9.0억$)과 `200899`(6.4억$)는 금액이 크지만 "그 밖의 것"이다.
홍삼가공품·건강기능식품·소스가 뒤섞여 있어 단일 소비자 개념으로 번역할 수
없다. **큰 값을 버리는 쪽이 잘못된 개념에 붙이는 것보다 낫다.**

결과: **30품목 중 18품목(46.8억$, 금액 기준 63%)을 14개 품목 개념으로 번역.**
제외 12품목의 사유는 전부 `--dropped`에 기록했다.

```
python build_food_dict.py --dropped    # 제외 12건과 사유
python build_food_dict.py --mapping    # HS → 개념 전체 대응표
```

**품목 마스터는 건드리지 않았다.** L1 지수는 30품목 전부로 계속 산출된다.
사전에서만 제외한 것이며, 6217 건에서 배운 원칙 그대로다 — 동결 후보는
검정 결과와 무관하게 유지하고, 파생 계열에서 조정하고 사유를 남긴다.

도메인 수준 3종은 **소비 양식**을 가른다 — 관심(`C01`) · 가정조리(`C02`) ·
외식(`C03`). 요리법 검색이 느는 것과 한식당 검색이 느는 것은 다른 현상이며,
수출과 연결되는 쪽은 전자에 가깝다. 나중에 어느 쪽이 `panel.csv`와 붙는지
자체가 발견이 된다.

김(121221)과 인삼(121120)이 들어 있는 것에 주목할 만하다. 이 둘은 BEC가
중간재로 분류하는 것을 **검정 전에** 예외로 확정해 품목 마스터에 넣은
품목이다. 그 결정이 이제 L3까지 이어진다.

### 위약 3종

같은 문법을 이웃 요리에 적용한다. "한국 음식 검색이 늘었다"는 아시아 음식
전반의 유행이거나 건강식 붐일 수 있다. **위약에서도 계수가 유의하면 통제가
불충분한 것이므로 결과를 채택하지 않는다.** 자국 요리 조합(일본에서 일식,
태국에서 태국음식)은 무의미하므로 제외해 P01·P02만 17행이다.

주의할 점 하나. 한식과 일식은 **대체재이자 보완재**라 위약 계수의 부호가
양쪽 다 나올 수 있다. 유의성만 보면 오독하므로 부호까지 함께 봐야 한다.
`remaining_risk`에 적어 두었다.

## 5. 일본 — 오염 위험이 가장 큰 시장

**일본은 거의 모든 한식 범주에 자국 대응물을 갖고 있다.**

| 개념 | 순진한 질의 | 실제로 재는 것 | 사전이 쓴 질의 |
|---|---|---|---|
| 라면 | `ラーメン` | **일본 라멘** | `韓国ラーメン` |
| 소주 | `焼酎` | **일본 소주(쇼추)** | `韓国焼酎` |
| 김 | `のり` | **일본산 김** | `韓国のり` |
| 김치 | `キムチ` | 일본 국내 생산분 포함 | `韓国キムチ` |

전 언어에서 한국 수식어를 붙였지만, 그만큼 **검색량이 줄어 과소측정될
위험**이 남는다. 완전한 해결책은 없다. 해당 4행에 `ambiguity_flag =
JP_DOMESTIC_COUNTERPART`를 달아 회귀 단계에서 따로 볼 수 있게 했다.

일본은 K-Food 주요 수출국이므로 이 오염은 사소한 문제가 아니다.

## 6. topic MID

**지어내지 않았다.** 기존 사전에 KFOOD 행이 없어 승계할 검증된 MID가 하나도
없다. 그래서 **358행 전부 keyword**로 냈다.

관광 사전은 기존 사전에서 실증된 MID 두 개(`/g/11h_5y_9w7`,
`/g/11t7fqrvlx`)를 승계할 수 있었다. K-Food는 그 자산이 없다.

다만 고유 개체로 볼 만한 개념 — 김치·고추장·소주·인삼·라면과 각국 요리 —
9종 160행에 `technical_status = PENDING_TOPIC_EXTRACTION`을 달았다. DOM
실측 때 MID를 우선 채택하고, 잡히지 않으면 keyword로 남긴다. 나머지 198행은
`Korean instant rice` 같은 합성 표현이라 애초에 개체가 아니므로 keyword
전용이다.

그럴듯한 MID를 채워 넣으면 전혀 다른 개념을 재면서도 검증란이 차 있어 아무도
의심하지 않는다. **가장 위험한 종류의 오류다.**

## 7. 중국

**제외한다.** Google Trends가 차단된 시장이다. 기존 486행 사전에도 중국이
없어 국가 명단은 18개국 그대로다.

K-Food의 경우 중국 결측이 K-Beauty만큼 치명적이지는 않다 — L1에서 K-Food의
최대 시장은 미국·일본·베트남이고 중국 의존도가 상대적으로 낮다. 그래도
`lock.json`의 `excluded`에 사유를 남긴다.

## 8. 동결

```
python build_food_dict.py --freeze
```

품목 마스터와 같은 규약이다. **결과를 보고 질의를 고치면 검정이 무효가 된다.**
`lock.json`에 `anchored_to` 로 품목 마스터 해시를 기록해 두 동결이 연결된
것임을 남긴다.

예외 하나 — **실증 실패(무신호)로 인한 탈락은 결과가 아니라 기술적
사유**이므로 동결 위반이 아니다. `KFOOD_I09`(어묵)는 직역어라 실제로 검색되지
않을 가능성이 높고, 탈락이 예상된다고 `remaining_risk`에 **미리** 적어
두었다. 예상을 사전에 적어 두면 사후 합리화와 구분된다.

## 9. 다음 단계

| 순서 | 할 일 | 상태 |
|---|---|---|
| 1 | 사전 검토·확정 | ← **지금** |
| 2 | `--freeze` 동결 | 대기 |
| 3 | Trends 실측 — 358행 신호 유무 + TOPIC 후보 160행 MID 추출 | **취득 경로 미정** |
| 4 | 무신호 탈락 + topic 승격 판정 | 대기 |
| 5 | 국가×월 시계열 수집 | 대기 |
| 6 | L1 `panel.csv`와 결합 → **S3 회귀 + 위약검정** | 대기 |

6번이 이 프로젝트에서 아직 아무도 답하지 않은 질문에 처음 닿는다 —
**"한국이 무엇을 얼마나 파는가"가 아니라 "그것이 한류 때문인가".**

3번이 막혀 있다. Trends 취득 경로(pytrends / 공식 API / 수동 CSV)를 정해야
하고, 관광 178행과 합치면 **536행**이라 수동은 사실상 불가능하다.

또 Trends는 요청당 최대 5개를 0~100으로 **상대 정규화**한다. 배치마다 척도가
달라 이어붙일 수 없으므로 **모든 배치에 공통 기준어(anchor)** 를 넣어
재척도화해야 한다. 5번 착수 전에 정할 항목이다.
