# 기준별 체크리스트의 이론적 근거

규정 심사위원(체크리스트 채점자)이 사용하는 기준별 10개 이진 항목의 설계 근거를
정리한다. 각 항목은 "이 사건이 대화에 있었는가"로 판정 가능해야 하며(이진성),
학술 문헌의 평가 구인(construct)에 대응해야 한다(타당성).

공통 설계 원칙: 각 기준의 항목 1~7은 해당 구인의 **입증 행위**를, 8~9는
**자기 인식**(약점·리스크의 선제 인정 — 본 시스템의 "약점 인정 = 가점" 철학)을,
10은 **논리적 일관성**을 판정한다.

---

## 1. 독창성 (Originality) — 창의성 연구 기반

**이론적 토대.**
- **창의성의 표준 정의** (Runco & Jaeger, 2012, *Creativity Research Journal*):
  창의적이려면 **새로움(novelty)과 유용성(usefulness)을 동시에** 갖춰야 한다.
  새롭기만 한 아이디어는 창의적인 것이 아니라 단지 특이한 것이다.
- **아이디어 평가 구인** (Dean, Hender, Rodgers & Santanen, 2006, *JAIS*,
  "Identifying Quality, Novel, and Creative Ideas"): 아이디어 품질을
  novelty(독창성·패러다임 관련성), workability, relevance, **specificity**의
  4차원으로 분해하고 확인적 요인분석으로 판별 타당도와 높은 평가자간 신뢰도를
  검증했다. 특히 novelty는 **기존 해법과의 비교를 통해서만** 측정 가능하다.

**항목과 근거:**

| ID | 항목 | 판정 내용 | 이론적 근거 |
|----|------|-----------|-------------|
| O1 | 기존 해법 식별 | 기존 해법·유사 시도를 구체적으로 언급했다 | novelty는 비교 대상 없이 성립 불가 (Dean et al.) |
| O2 | 차별점 명시 | 기존 해법과의 차이를 구체적으로 진술했다 | novelty의 조작적 정의 |
| O3 | 차별점의 검증 가능성 | 차별점을 제3자가 확인 가능한 형태(기능·구조·수치)로 제시했다 | specificity 차원 (Dean et al.) |
| O4 | 공백의 설명 | 왜 아직 없는지/왜 지금 가능해졌는지를 설명했다 | H-창의성 검증 (Boden의 역사적 새로움) |
| O5 | 모방 장벽 | 차별점이 쉽게 모방되지 않는 이유를 제시했다 | 지속 가능한 novelty |
| O6 | 관점 전환 | 문제를 다르게 정의하거나 기존 프레임을 벗어난 요소가 있다 | paradigm relatedness (Dean et al.의 novelty 하위차원) |
| O7 | 새로움-가치 연결 | 새로움이 사용자 가치로 이어짐을 설명했다 | novelty+usefulness 결합 (표준 정의) |
| O8 | 유사 사례 반례 대응 | "이미 있지 않나" 류의 반례에 정면 대응했다 | 논박(elenchus) 통과 |
| O9 | 독창성 한계 인정 | 독창성의 한계(부분적 새로움)를 스스로 인정했다 | 자기 인식 가점 원칙 |
| O10 | 무모순 | 독창성 주장이 대화 전체에서 모순되지 않는다 | 일관성 |

## 2. 실용성 (Practicality) — 타당성 분석 기반

**이론적 토대.**
- **TELOS 프레임워크** (정보시스템 타당성 조사의 표준): Technical(기술),
  Economic(경제), Legal(법적), Operational(운영), Schedule(일정)의 5개 차원으로
  실행 가능성을 분해한다.
- **Real-Win-Worth 스크리닝** (George Day, 2007, *Harvard Business Review*,
  "Is It Real? Can We Win? Is It Worth Doing?"): "실현 가능한가(Real)"를
  시장의 실재와 제품의 실현 가능성으로 분해해 검증한다. 3M이 1,500개 이상의
  프로젝트에 적용한 검증된 스크린이다.
- **린 스타트업의 MVP** (Ries, 2011): 실용성 주장은 최소 실행 버전의 구체적
  정의로 입증된다.
- Dean et al.(2006)의 **workability** 차원: 알려진 제약을 위반하지 않고 쉽게
  구현될 수 있는가.

**항목과 근거:**

| ID | 항목 | 판정 내용 | 이론적 근거 |
|----|------|-----------|-------------|
| P1 | 자원 구체화 | 필요 인력·기술·예산을 수치나 구체 항목으로 제시했다 | TELOS: Technical/Economic |
| P2 | MVP 정의 | 최소 실행 버전의 범위를 구체적으로 한정했다 | 린 스타트업 MVP |
| P3 | 핵심 장애물 식별 | 실행의 가장 큰 장애물을 스스로 특정했다 | R-W-W: 리스크 식별 |
| P4 | 장애물 대응책 | 그 장애물에 대한 현실적 대응 방안을 제시했다 | workability (Dean et al.) |
| P5 | 구현 경로 | 핵심 기능의 구현 방법(데이터·기술·절차)을 설명했다 | TELOS: Technical |
| P6 | 비용 대비 효과 | 비용과 기대 효과를 비교하는 논리를 제시했다 | TELOS: Economic |
| P7 | 운영 주체 특정 | 누가 실행·운영하는지를 특정했다 | TELOS: Operational |
| P8 | 단계적 경로 | 시작→확장의 단계적 실행 순서를 제시했다 | TELOS: Schedule |
| P9 | 실행 리스크 인정 | 실행상 리스크·불확실성을 스스로 인정했다 | 자기 인식 가점 원칙 |
| P10 | 무모순 | 실용성 주장이 대화 전체에서 모순되지 않는다 | 일관성 |

## 3. 수용태도 (Acceptance) — 기술 수용·혁신 확산 이론 기반

**이론적 토대.**
- **혁신 확산 이론** (Rogers, 2003, *Diffusion of Innovations*): 혁신의 수용을
  결정하는 5개 속성 — 상대적 이점(relative advantage), 적합성(compatibility),
  복잡성(complexity), 시험 가능성(trialability), 관찰 가능성(observability) —
  이 수용 변량의 49~87%를 설명한다.
- **기술수용모형 TAM** (Davis, 1989, *MIS Quarterly*): 수용 의도는
  **지각된 유용성**(perceived usefulness)과 **지각된 사용 용이성**(perceived
  ease of use)이 결정한다.
- 이해관계자 분석: 수용은 사용자만이 아니라 손해 보는 집단의 저항까지 포함한다.

**항목과 근거:**

| ID | 항목 | 판정 내용 | 이론적 근거 |
|----|------|-----------|-------------|
| A1 | 수용 주체 특정 | 사용자·이해관계자를 구체적으로 특정했다 | 수용은 주체 없이 성립 불가 |
| A2 | 상대적 이점 | 현재 방식 대비 사용자가 얻는 이점을 구체화했다 | Rogers: relative advantage / TAM: 유용성 |
| A3 | 전환 비용 | 갈아타는 데 드는 비용·노력·학습을 다뤘다 | Rogers: complexity / TAM: 용이성 |
| A4 | 적합성 | 사용자의 기존 습관·가치와의 정합을 설명했다 | Rogers: compatibility |
| A5 | 시험 가능성 | 부담 없이 먼저 써볼 수 있는 경로를 제시했다 | Rogers: trialability |
| A6 | 반대 세력 식별 | 반대하거나 손해 보는 이해관계자를 식별했다 | 이해관계자 분석 |
| A7 | 저항 대응 | 반대·저항에 대한 대응 논리를 제시했다 | 확산 장벽 관리 |
| A8 | 확산 경로 | 초기 사용자 확보와 확산 방법을 구체화했다 | Rogers: observability·확산 곡선 |
| A9 | 수용 리스크 인정 | 수용되지 않을 가능성·조건을 스스로 인정했다 | 자기 인식 가점 원칙 |
| A10 | 무모순 | 수용태도 주장이 대화 전체에서 모순되지 않는다 | 일관성 |
