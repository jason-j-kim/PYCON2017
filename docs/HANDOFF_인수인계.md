# 인수인계 문서 — 정책 아이디어 평가 시스템

> 이 문서 하나로 이전 대화 기록 없이 작업을 이어받을 수 있도록 작성했다.
> 시스템의 현재 상태, 확보한 실증 결과, 미해결 문제, 그리고 **다시 논의하지 않아도
> 되는 결정들**을 담았다.
>
> 최종 갱신 시점의 저장소 HEAD: `5fd92e8`

## 0. 30초 요약

국민이 제안한 정책 아이디어를 **AI가 소크라테스식 문답으로 캐묻고**, 그 대화를
근거로 **국가 데이터 4종에 대조해 선례를 검증**하는 시스템이다. 「온 국민 아이디어
등록제」를 염두에 두고 개발했다.

두 가지 형태로 작동한다 — 연구용 **터널**(로컬 서버 + cloudflared)과 공개용
**Vercel** 배포다. 둘 다 현재 작동한다.

개발 과정에서 **연구로 발표할 만한 실증 결과**가 나왔고(특히 측정 재현성 문제와
LLM 도구 격차), 그에 대한 KDI형 연구 초안 2편이 작성되어 있다.

## 1. 시스템 구조

### 1.1 전체 흐름

```
① 소크라테스 문답 (12문·5단계)
        ↓
② 축 A: 이원 채점        축 B: 선례 검증 (4개 통로)
        ↓
③ 5문장 결과 + 2×2 위치 판정
```

**핵심 원칙: 먼저 대화, 그 다음 평가.** 아이디어 문장만 보고 선례부터 조회하지
않는다. 짧은 제안문에는 대상·수단·전달경로·재원이 빠져 있어 그대로 검색하면
엉뚱한 선례가 걸리기 때문이다.

### 1.2 축 A — 대화와 채점

**12문답 5단계** (`socratic/engine.py`의 `STAGES`)

| 단계 | 문항 | 캐내는 것 |
|---|---|---|
| 명료화 | 2 | 대상·문제·방법의 한 문장 정의 |
| 독창성 | 3 | 기존 해법과의 차이, 모방 장벽 |
| 실용성 | 3 | 필요 자원, 최대 장애물, MVP |
| 수용태도 | 3 | 사용자, 전환 비용, 반대 이해관계자 |
| 자기평가 | 1 | 스스로 인정하는 약점 |

**이원 채점** — 같은 대화 로그를 두 방식으로 채점한다.
- **체크리스트**: 기준별 10항목 × 3기준 = 30항목. "이 사건이 대화에 있었는가"만
  이진 판정. 충족 개수 = 0~10점. 인용 없으면 자동 불충족.
- **종합판단**: 대화 전체를 읽고 기준별 0~10점 + 판단 근거.

**결합 규칙** (2026-08 수정)
```
|체크리스트 − 종합판단| < 3  →  평균
|체크리스트 − 종합판단| ≥ 3  →  낮은 쪽 채택   ← DIVERGENCE_LIMIT
```
가중치 고정: 독창성 35% · 실용성 35% · 수용태도 30%.

**체크리스트의 이론적 근거** (`docs/checklist-rationale.md`)
독창성 = Runco & Jaeger 창의성 표준정의 + Dean et al.(2006) /
실용성 = TELOS + Real-Win-Worth(Day, HBR 2007) + 린 MVP /
수용태도 = Rogers 확산이론 + Davis TAM

> ⚠️ **알려진 결함**: TELOS의 Legal(법적 타당성)이 P1~P10에 없다. Rogers 5속성 중
> 복잡성·관찰가능성이 빠졌다. 발표 시 지적받을 지점이다.

### 1.3 축 B — 검증 통로 4개

각 통로는 **서로 다른 질문에 답한다.** 이것이 설계의 핵심이다.

| 통로 | 질문 | 데이터 | 구현 |
|---|---|---|---|
| ① 재정 | 예산이 붙어 **집행**됐나 | 세출예산 14,122개 사업 (로컬 `fiscal.json`) | `_fiscal_local_search` |
| ② KDI 연구 | 연구로 **검토**됐나 | 발간물 7,362건 (로컬 `kdi.sqlite`) | **kdinov** (아래) |
| ③ 국회 의안 | **입법**이 시도됐나 | ALLBILLV2 API | `_bill_lookup` |
| ④ 해외사례 | 다른 나라가 **시행**했나 | OECD OPSI 1,015건/98개국 (로컬) | `_opsi_lookup` |

**근거 등급을 분리한다.** A급(조회로 확인)과 B급(모델 기억)을 구분하고, B급은
고유명사 인용을 금지한다. 해외는 각국 **자기 신고** 자료이므로 성과 미검증임을
별도 표기한다.

**미발견은 비대칭 처리.** 발견은 강한 증거, 미발견은 약한 증거. 미발견 시 확신도에
상한(최대 '중')을 두고 어느 영역을 못 덮었는지 기록한다.

### 1.4 kdinov — KDI 정밀 판정기

`kdinov/` 디렉터리. 별도 프로젝트를 통합한 것으로, 단순 키워드 조회보다 훨씬
정교하다.

- **자동 분해**: 아이디어 문장을 `대상 × 수단 × 영역`으로 분해(`decompose_policy_idea`)
- **2차원 판정**: 중첩도 `N0`(동일)~`N4`(무관) × 역할 `실행/경합/근거/선례/무관`
  - `실행`(법령·시행령·보도자료) = 강한 반증
  - `근거`(효과분석만) = 감점이 아니라 **인용처**
- **방향성 역전 감지**: "정부가 AI를 쓴다" vs "기업이 AI를 배운다" 구분
- **재현율 통제**: `known_positives` 미회수 시 판정 `VOID`

우리 시스템은 **명세의 대상·수단·전달경로·재원을 이어붙인 전체 문장**을 kdinov에
넘긴다(키워드보다 정확). `_kdi_idea_text()` 참조.

## 2. 배포 형태 두 가지

### 2.1 터널 (연구용)

Claude Code CLI(Pro 로그인)를 사용하므로 **API 키 불필요**.

```bat
REM 창 1 — 서버
cd C:\Users\user\PYCON2017
set SOCRATIC_ACCESS_CODE=art2026
python webapp\app.py
REM → http://localhost:8000/policy

REM 창 2 — 외부 공개 터널(선택)
cloudflared tunnel --url http://localhost:8000
REM → https://○○○.trycloudflare.com/policy  (실행할 때마다 주소 바뀜)
```

**자주 나는 오류**
| 증상 | 원인·해결 |
|---|---|
| `[Errno 10048]` 포트 사용 중 | 이전 서버가 살아 있음 → `taskkill /F /IM python.exe` |
| `No such file or directory` | 폴더가 틀림 → `cd /d C:\Users\user\PYCON2017` |
| 터널은 뜨는데 페이지 안 열림 | 서버가 안 켜짐 → **localhost부터** 확인 |

**환경변수**
| 이름 | 용도 |
|---|---|
| `SOCRATIC_ACCESS_CODE` | 초대 코드(현재 `art2026`). 미설정 시 접근 통제 꺼짐 |
| `DATA_GO_KR_KEY` | PRISM용(현재 미사용) |
| `ASSEMBLY_KEY` | 국회 의안 API |
| `KDI_SQLITE` | kdinov 코퍼스 경로(기본 `kdi/kdi.sqlite`) |
| `PRISM_ENABLED` | PRISM 부활용(기본 `0`) |
| `DIVERGENCE_LIMIT` | 괴리 임계(기본 `3`) |

### 2.2 Vercel (공개용)

- 루트 `web/`, 첫 화면 `web/index.html` (주소 끝에 `/policy` 안 붙임)
- **BYOK** — 사용자가 브라우저에 자기 Claude API 키 입력. 서버에 저장 안 함
- 채점은 브라우저에서 수행(`combineScores`가 터널의 `_combine`과 동일 규칙)
- 코퍼스는 `web/api/`에 번들 커밋됨 (`kdi.sqlite` 26MB, `opsi_policies.db`)
- push하면 자동 재배포

### 3.2 OPSI 해외 코퍼스 (1,015건 / 98개국)

**수집 경위가 중요하다.** OECD OPSI 사이트는 Cloudflare로 보호되어 자동 수집이
모두 차단됐다(requests 403, Playwright 헤드리스·헤드풀 모두 Turnstile 차단).

**여기서 방침을 정했다 — 봇 우회는 하지 않는다.** KDI 같은 국가기관이 우회로
데이터를 긁는 모양새는 부적절하다고 판단했다. 유료 해외 정책DB(Overton)도
"외국 상용 서비스 의존"이라는 이유로 배제했다.

최종적으로는 사람이 정리한 Obsidian Vault 형태의 SQLite를 임포트해 해결했다
(`overseas/import_obsidian_vault.py`). 본문 8개 필드(문제·해법·혁신요소·성과·
실패요인·성공조건·복제성·교훈)가 전부 들어 있다.

관련 문서: `overseas/OPSI_수집절차.md`, `docs/OPSI_해외정책사례_수집절차.docx`

### 3.3 PRISM 중단

data.go.kr PRISM API가 불안정해 **기본 정지**시켰다(`PRISM_ENABLED=0`). '검토(연구)'
슬롯은 KDI 로컬 코퍼스가 대체한다. 되살리려면 환경변수만 켜면 된다.

## 4. 확보한 실증 결과 (전부 재현 가능)

### 4.1 판별력 — n=10, 극단 사례 한정

`simulation/REPORT.md`. 진부 5건 vs 창의 5건.

| 그룹 | 평균 | 표준편차 |
|---|---|---|
| 진부 | 4.23 | 0.67 |
| 창의 | 8.50 | 0.32 |

분포 겹침 없음. **단, 극단 사례만 시험했고 문항을 모델이 생성했다.** 실제 제안은
중간대에 몰리므로 **경계 사례 판별력은 미확인**이다.

### 4.2 측정 재현성 문제 ★ 가장 중요한 발견

동일한 대화 로그를 체크리스트로 **4회 채점**한 결과:

| 회차 | 독창성 | 실용성 | 수용태도 | 합계 |
|---|---|---|---|---|
| 기록값 | 4 | 7 | 5 | 16 |
| 재채점 1 | 4 | 6 | 4 | 14 |
| 재채점 2 | 5 | 7 | 5 | **17** |
| 재채점 3 | 3 | 5 | 5 | **13** |

**같은 입력에 13~17** (30점 척도, 평균 15.0). 체크리스트는 "사건이 있었는가"만
판정하는 기계적 절차로 설계했고 **재현성이 그 정당화 근거**였는데, 성립하지 않는다.

이는 시스템의 실제 결함이자 연구 주제다. 재현 방법:
```python
import sys; sys.path.insert(0,'.')
from socratic import engine as e
import json
tr = '\n'.join(json.load(open('simulation/results/trial_01_banal.json',encoding='utf-8'))['transcript'])
r = e._grade_checklist(tr)   # 여러 번 돌려 보라
```

### 4.3 LLM 도구 격차 ★ 두 번째 중요 발견

외부 연구자가 수행한 통제 비교. 동일 아이디어에 대해 (A) 인간 직접 응답 vs
(B) 제미나이 답변 복사.

| | 총점 | 체크/종합 합계 | 실질 독창성 판정 |
|---|---|---|---|
| A 인간 | **5.2** | 14 / 17 | 계열 내 변형 · 보류 |
| B AI | **8.0** | 28 / 20 | 계열 밖 시도 · 추진 |

**격차의 82%가 체크리스트에서 발생**했다(가중 분해로 재계산해도 82.3%). 종합판단은
+3에 그쳤고 **실용성은 6→6으로 동일**했다. 즉 내용의 질을 보는 채점자는 두 세션을
거의 같게 봤다.

원인은 분량이 아니라 **채점 항목의 열거**다. 아래 4.4가 그 근거다.

또한 **축 B까지 오염**됐다. AI는 기존 제도와 겹치는 부분(피추천인 감면)을 주장에서
빼고 신규한 부분(추천자만)만 남겼다 — 표현력이 아니라 **주장 범위 설정 전략**이다.

### 4.4 조작 내성 — 분량 가설 기각

같은 내용을 **길지만 내용 없게** 재작성한 로그를 3회씩 채점:

| 대상 | 길이 | 3회 평균 | 범위 |
|---|---|---|---|
| 원본 | 3,545자 | 15.0 | 13~17 |
| 장황본 | 5,160자(1.46배) | **13.0** | 12~14 |

**길이를 1.46배로 늘려도 점수가 오르지 않았다**(오히려 하락). 관측 격차(체크 14점)는
측정 변동폭(4점)의 3.5배라 잡음으로 설명되지 않는다.

### 4.5 완화 장치 — 괴리 임계 규칙

두 채점이 3점 이상 벌어지면 낮은 쪽 채택.

| | 규칙 전 | 규칙 후 |
|---|---|---|
| A 인간 | 5.2 | **5.2** (불변) |
| B AI | 8.0 | **7.0** |
| 격차 | 2.8 | 1.8 (36%↓) |

**인간 조건을 침해하지 않고 부풀려진 쪽만 보정**한다는 점이 이 규칙의 장점이다.

> ⚠️ 다만 임계값 3은 **이 자료를 보고 고른 값**이다(관측 괴리와 정확히 일치, 4로
> 두면 무효). 표본 내 적합이므로 별도 표본에서 검증해야 한다.

|---|---|---|---|
| 1 | **측정 재현성** — 동일 입력에 13~17 | 확인됨, 미해결 | 도입 차단 사유 |
| 2 | **전문가 판정과의 일치도** | 심사지만 준비, 미실시 | 준거 타당도 없음 |
| 3 | **경계 사례 판별력** | 미확인 (극단만 시험) | 실제 운영의 핵심 |
| 4 | **체크리스트 열거 취약성** | 원인 규명됨, 미수정 | 도구 격차의 82% |
| 5 | **프롬프트 캐싱** | 미구현 | 비용 추계가 낙관적 |
| 6 | TELOS Legal 항목 누락 | 미수정 | 정책 평가에서 법적 타당성 미평가 |
| 7 | 가중치 35/35/30의 근거 | 없음, 감도분석 미실시 | 임의 가중치가 결과 좌우 |
| 8 | 총소유비용(TCO) 추계 | 미실시 | 예산 심의 대응 불가 |

### 문제 4의 처방 (설계 완료, 미적용)
체크리스트를 **'언급 여부'에서 '검증 가능성'으로 격상** — 항목별로 수치·주체·시점
중 최소 하나를 요구. 열거만으로는 못 채우게 된다.
**적용하지 않은 이유**: 채점 기준 변경이라 기존 세션과의 비교 가능성이 깨진다.
사용자가 "2번은 변경하지 말자"고 명시적으로 보류시켰다.

## 10. 주의사항

- **정부 API 키를 커밋하지 말 것.** 환경변수로만 전달.
- **`kdi/*.sqlite`, `overseas/*.db`는 gitignore됨.** 단 `web/api/`의 코퍼스는
  Vercel 배포용이라 의도적으로 커밋되어 있다.
- **초대 코드가 담긴 배치파일(`run_policy.bat`)은 gitignore됨.**
- 서버를 끌 때는 `Ctrl+C`로. 강제 종료하면 포트 8000이 남아 `10048` 오류가 난다.
- 발표자료·연구초안의 수치를 인용할 때는 **본 문서 4장의 단서 조항**을 함께 읽을 것.
  특히 n=1·n=10 규모와 "통제되지 않은 비교"라는 지위를 빠뜨리면 과장이 된다.
