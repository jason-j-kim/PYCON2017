정책 아이디어 평가 시스템 · 외부 배포

대화와 선례 검증, 두 갈래 배포 구조

평가 모델은 두 배포에서 완전히 동일하다. 12문답도, 이원 채점도, 네 통로의 선례 검증도 같은 규칙을 쓴다. 갈라지는 것은 하나뿐이다 — 누가 오케스트레이션을 하고, Claude를 어떻게 부르는가.

공통 평가 모델

두 배포가 공유하는 네 단계. 프롬프트·채점 기준·판정 규칙이 동일하다.

01 소크라테스 문답 12문 5단계 · 명료화 2 · 독창성 3 · 실용성 3 · 수용태도 3 · 자기평가 1
02 이원 채점 체크리스트 30항목 + 종합판단. 두 채점이 3점 이상 벌어지면 낮은 쪽 채택
03 선례 검증 명세 추출 → 4통로 조회 → 근거 등급 A/B 부착 → 4구간 밴드 판정
04 산출 5문장 결과 + 2×2 위치 판정. 새 모델 호출 없이 기존 결과를 재조립

네 통로 중 셋이 로컬이다. 외부로 나가는 통신은 Claude 호출과 국회 의안 조회 둘뿐이며, 나머지는 폐쇄망에서도 그대로 작동한다. 터널판은 원본 코퍼스를 그대로 두고, API판은 본문을 덜어낸 경량본을 배포에 번들한다.

기관 서버 도입 시

두 배포 모두 그대로는 옮길 수 없다

터널판의 제약
Claude Code CLI에 개인 계정으로 로그인한다. 대화형 로그인이 필요해 무인 서버에서 유지하기 어렵고, 과금과 감사 추적이 개인에게 귀속된다.
API판의 제약
이용자마다 자기 키를 넣는 구조다. 기관이 단일 계정으로 비용을 관리하고 이용 이력을 남기는 운영 방식과 맞지 않는다.

기관 서버에 필요한 것은 제3의 구성이다 — 오케스트레이션과 상태 관리는 터널판의 서버 방식을 쓰고, Claude 호출만 API판의 방식으로 바꾸되 키를 기관 환경변수에 둔다.

구현 범위는 좁다. engine.call_claude()에 분기를 하나 넣어 ANTHROPIC_API_KEY가 있으면 API로, 없으면 기존 CLI로 가게 하면 연구용 사용을 전혀 건드리지 않고 서버 구성이 가능해진다.
