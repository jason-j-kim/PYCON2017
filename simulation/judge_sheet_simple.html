심사 지침

  1. 이 채점표에는 서로 다른 아이디어 평가 세션 2개(세션 A, B)의 대화 전문이 실려 있습니다. 각 세션은 제안자가 아이디어를 제출하고 12개의 질문에 답한 기록입니다.
  2. 채점 대상은 아이디어 자체가 아니라 제안자가 질문에 얼마나 잘 답했는가 — 방어의 성실성과 논리적 견고함 — 입니다.
  3. 세션마다 ① 대화 전문 통독 → ② 채점표 기입 순서로 진행하십시오. 한 세션을 끝낸 뒤 다음 세션으로 넘어가십시오.
  4. 다른 심사위원과 상의하지 마십시오.
  5. 동일한 대화에 대한 AI의 채점 결과가 존재하지만 비공개입니다. 모든 심사위원의 채점이 끝난 뒤 대조합니다.

세션 A — 대화 전문

제안된 아이디어
냉장고 속 재료를 입력하면 만들 수 있는 요리를 추천해주는 앱이에요. 사람들이 냉장고에 뭐가 있는지 몰라서 음식을 버리는 경우가 많으니까 많은 사람들이 좋아할 것 같아요.
[턴 1] 제안자냉장고 속 재료를 입력하면 만들 수 있는 요리를 추천해주는 앱이에요. 사람들이 냉장고에 뭐가 있는지 몰라서 음식을 버리는 경우가 많으니까 많은 사람들이 좋아할 것 같아요.
[턴 2] 질문자(명료화)냉장고 재료 입력과 요리 추천이라는 방법은 나왔는데, 이걸 누가 쓸지가 아직 안 보이네요. 자취생, 맞벌이 부모, 혹은 다른 누군가 중에서 이 앱이 가장 절실한 사람은 구체적으로 누구인가요?
[턴 3] 제안자자취생들이 제일 많이 쓸 것 같아요. 요리를 잘 못하는데 냉장고에 재료는 있으니까 그런 분들한테 편리할 것 같아요. 사실 맞벌이 부모님들도 바쁘시니까 다 같이 쓰실 수 있을 것 같긴 해요.
[턴 4] 질문자(명료화)자취생과 맞벌이 부모, 둘 다 넣으니 다시 범위가 넓어졌네요. 이 두 그룹을 하나로 묶어주는 공통점이 '시간이나 요리 실력이 부족하다'는 것이라면, 대상과 문제와 방법을 합쳐서 한 문장으로 이 앱을 정의하면 어떻게 표현하실 수 있을까요?
[턴 5] 제안자시간 없고 요리 실력 부족한 사람들이 냉장고 재료만 입력하면 바로 요리를 추천받는 앱, 이렇게 정의하면 될 것 같아요.
[턴 6] 질문자(독창성)한 문장으로 명확하게 정리하셨네요. 그런데 만개의레시피나 해먹남녀 같은 앱도 이미 재료 입력하면 레시피를 추천해주는데, 이 앱이 그런 기존 서비스들과 다른 점은 무엇인가요?
[턴 7] 제안자그런 앱들보다 좀 더 편리하게 만들 것 같아요. 화면도 더 간단하고 사용하기 쉽게 해서 사람들이 더 편하게 느낄 수 있도록 하면 차별화가 될 것 같아요.
[턴 8] 질문자(독창성)'더 편리하고 간단하게'라는 답은 다른 앱들도 똑같이 주장할 수 있는 말이라, 실제로 무엇이 다른지 잘 안 보이는데요. 만약 경쟁 앱이 다음 주에 화면을 똑같이 간단하게 바꾼다면, 그래도 남아있을 이 앱만의 차별점은 무엇일까요?
[턴 9] 제안자음... 그렇게 물으시니 딱히 확실한 차별점은 없는 것 같아요. 그래도 사람들이 쓰다 보면 저희 앱이 좀 더 편하다고 느끼지 않을까 싶긴 한데, 정확히 뭐가 다르다고 콕 집어 말씀드리긴 어렵네요.
[턴 10] 질문자(독창성)차별점을 콕 집어 말하기 어렵다는 걸 솔직하게 인정하신 게 다음 질문으로 넘어갈 좋은 출발점이네요. 그럼 관점을 바꿔서, 냉장고 재료 입력 자체가 아니라 그 다음 단계에서 이 앱만 해결해줄 수 있는 아주 구체적인 불편함이 하나 있다면 무엇일까요?
[턴 11] 제안자음, 요리 추천받고 나서 부족한 재료 있으면 바로 장보기 리스트로 연결해주는 것 정도가 있을 것 같아요. 그러면 사람들이 좀 더 편하게 느끼지 않을까 싶어요.
[턴 12] 질문자(실용성)장보기 리스트 연동이라는 구체적인 기능을 짚으셨네요. 그런데 이걸 실제로 만들려면 재료 인식, 레시피 매칭, 장보기 연동까지 꽤 여러 기능이 필요해 보이는데, 지금 가진 자원(시간, 돈, 인력)으로 가장 먼저 만들어서 사람들에게 보여줄 수 있는 최소 버전은 어디까지인가요?
[턴 13] 제안자일단 재료 입력하면 레시피 추천해주는 기본 기능부터 만들어서 보여주면 될 것 같아요. 장보기 리스트 연동 같은 건 나중에 반응 좋으면 그때 추가하면 되지 않을까 싶어요.
[턴 14] 질문자(실용성)기본 기능부터 시작하겠다는 우선순위는 명확해졌네요. 그런데 그 기본 기능, 즉 재료 입력해서 레시피 추천해주는 부분을 직접 만들려면 어떤 기술이나 데이터베이스가 필요한지, 그리고 그걸 준비하는 데 실제로 어느 정도의 시간과 비용이 들 것 같으신가요?
[턴 15] 제안자레시피 데이터베이스는 인터넷에 있는 자료들 모아서 만들면 될 것 같고, 개발자 한두 명 정도 있으면 몇 달 안에 만들 수 있지 않을까 싶어요. 비용은 정확히 계산은 안 해봤는데 그렇게 크게 들지는 않을 것 같아요.
[턴 16] 질문자(실용성)인터넷 자료를 모아서 만든다고 하셨는데, 레시피 데이터를 그렇게 수집하면 저작권 문제나 데이터 정확성 문제가 생길 수도 있을 것 같은데요. 그 부분은 어떻게 해결할 계획이신가요?
[턴 17] 제안자그 부분은 저도 좀 걱정되긴 하는데, 출처를 밝히거나 하면 어느 정도 괜찮지 않을까 싶어요. 정확한 해결 방법은 아직 구체적으로 생각해보진 못했어요.
[턴 18] 질문자(수용태도)저작권 문제까지 아직 구체적 답은 없지만 걱정되는 지점을 스스로 짚어내신 건 의미가 있네요. 그런데 지금 자취생이 이미 쓰고 있는 만개의레시피나 유튜브 레시피 영상 같은 익숙한 방법이 있을 텐데, 그 사람이 그걸 버리고 굳이 이 앱으로 갈아탈 이유가 뭐라고 생각하시나요?
[턴 19] 제안자그게... 저희 앱이 재료 입력만으로 바로 추천해주니까 검색하는 것보다는 조금 더 편해서 갈아탈 것 같긴 한데, 확실히 그 사람들이 꼭 갈아탈 이유라고 하면 딱히 강한 이유는 없는 것 같아요. 그냥 써보다가 편하면 계속 쓰지 않을까 싶어요.
[턴 20] 질문자(수용태도)강한 이유가 없다는 걸 인정하신 점이 솔직하네요. 그렇다면 만약 만개의레시피 같은 기존 앱이 '재료 입력하면 바로 추천' 기능을 그대로 추가한다면, 자취생들이 굳이 이 앱을 새로 설치하고 배우는 수고를 감수할 이유가 그때도 남아있을까요?
[턴 21] 제안자그렇게 되면 사실 남아있을 이유가 별로 없을 것 같긴 해요. 그래도 저희가 좀 더 신경 써서 만들면 사람들이 알아봐 주지 않을까 하는 기대는 있는데, 확실한 이유라고 말씀드리긴 어렵네요.
[턴 22] 질문자(수용태도)남아있을 이유가 별로 없다는 걸 두 번째로 인정하신 거네요, 이 지점은 꽤 중요해 보입니다. 그럼 반대로, 이 앱이 나왔을 때 오히려 불편해지거나 손해를 본다고 느낄 사람이나 집단이 있을까요?
[턴 23] 제안자음... 딱히 손해 볼 사람은 없을 것 같은데요. 그냥 다들 편하게 쓰기만 하지 않을까 싶어서, 손해 보는 쪽은 잘 떠오르지 않네요.
[턴 24] 질문자(자기 평가)지금까지 차별점이 불확실하다는 점, 기존 앱이 따라오면 남을 이유가 없다는 점을 스스로 짚어주셨는데요. 이 대화를 돌아봤을 때, 이 아이디어가 실제로 세상에 나가기 전에 가장 먼저 보완해야 할 약점 하나를 꼽는다면 무엇이고, 그걸 어떻게 채워나가실 건가요?
[턴 25] 제안자아무래도 차별점이 없다는 게 가장 큰 약점인 것 같아요. 그건 좀 더 고민해서 저희만의 특징을 찾아봐야 할 것 같은데, 구체적으로 어떻게 해야 할지는 아직 저도 잘 모르겠어요. 일단 사람들 의견도 들어보고 하면서 차차 채워나가야 하지 않을까 싶어요.

세션 A — 채점표 (종합판단)

숙련된 심사위원으로서 전체적 인상으로 채점하십시오 — 답변의 논리적 흐름, 태도의 진정성, 논증 전체의 설득력을 통합해서 판단하되, 근거는 대화의 턴 번호를 인용해 적으십시오. 약점의 솔직한 인정은 감점이 아니라 가점 요인입니다. 채점 대상은 아이디어 자체가 아니라 제안자의 답변입니다.

점수 밴드기준
0~2회피·공허한 주장. 근거가 거의 없고 같은 질문에 두 번 이상 모호하게 답함
3~4주장은 있으나 뒷받침이 빈약. 구체성 없이 일반론으로 답함
5~6구체적 근거를 일부 제시하고 논리를 대체로 유지하나 빈틈이 여럿 남음
7~8일관된 논증 + 검증 가능한 근거 + 자기 약점 인식이 모두 나타남
9~10반례와 전제 공격까지 정합적으로 소화하며 심사위원을 설득해 냄

세션 B — 대화 전문

제안된 아이디어
버스가 몰려서 다니는 문제를 데이터로 풀어보고 싶습니다. 교통카드 태그 데이터로 정류장 혼잡을 예측해서, 만원 버스가 다가오면 다음 사거리 신호를 3~5초만 늘려주는 식으로 배차 간격을 자동으로 벌리는 겁니다. 서울시 TOPIS 데이터가 이미 있으니 새 센서 없이 가능할 것 같고, 싱가포르에서 비슷한 방식으로 배차 편차를 18% 줄인 사례도 있습니다.
[턴 1] 제안자버스가 몰려서 다니는 문제를 데이터로 풀어보고 싶습니다. 교통카드 태그 데이터로 정류장 혼잡을 예측해서, 만원 버스가 다가오면 다음 사거리 신호를 3~5초만 늘려주는 식으로 배차 간격을 자동으로 벌리는 겁니다. 서울시 TOPIS 데이터가 이미 있으니 새 센서 없이 가능할 것 같고, 싱가포르에서 비슷한 방식으로 배차 편차를 18% 줄인 사례도 있습니다.
[턴 2] 질문자(명료화)TOPIS 데이터와 GLIDE 사례까지 구체적인 수치로 근거를 밝혀주신 점이 인상적입니다. 이 아이디어를 한 문장으로 압축한다면, "누구를 대상으로, 어떤 문제를, 어떤 방법으로 해결한다"는 형태로 어떻게 정리하시겠어요?
[턴 3] 제안자한 문장으로 하면… 서울 시내버스 승객을 대상으로, 출퇴근 시간에 버스가 몰려 다니는 문제를, 이미 있는 교통카드 데이터와 신호 연동으로 배차 간격을 자동 조정해서 푸는 겁니다. 목표는 배차 편차를 지금 4분대에서 3분 안쪽으로 줄이는 거고요.
