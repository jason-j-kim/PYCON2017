■ 착수 전에 셋만 확인해 주십시오

  셋 다 서버 담당자가 아니면 풀 수 없는 것이고, 설치를 다 끝낸 뒤에
  발견하면 원인을 찾기 어렵습니다.

  (1) 방화벽에서 api.anthropic.com 으로 나가는 통신
      → 막히면 아무것도 되지 않습니다.
      지금 확인:  curl -sI https://api.anthropic.com/v1/messages -X POST
      401 이 나오면 정상입니다(키를 안 보냈으니 거부하는 것이고,
      통신 자체는 닿았다는 뜻). 아무 응답도 없으면 막힌 것입니다.

  (2) IIS 모듈 두 개 — URL Rewrite · Application Request Routing
      → 없으면 앞단 규칙이 조용히 무시되고 404 만 납니다.

  (3) 도메인 하나와 HTTPS 인증서
      → 방문자가 화면에 자기 API 키를 붙여넣습니다.
      평문으로 받으면 그 키가 도중에 드러납니다.

  윈도우에는 systemd 가 없습니다. 서비스로 만드는 길이 셋인데
  이 판은 셋째를 씁니다.

    NSSM         가장 흔하지만 외부 실행 파일을 따로 받아야 합니다.
                 기관 서버에 출처가 분명하지 않은 바이너리를 들이는 것은
                 승인이 어렵습니다.
    pywin32      꾸러미를 하나 더 깔고 서비스 클래스를 써야 합니다.
    작업 스케줄러  윈도우에 이미 들어 있습니다. 받을 것이 없습니다. ← 이것

  작업 스케줄러도 부팅 시 자동 실행 · 실패 시 재시작 · 로그온 없이 실행을
  모두 합니다. services.msc 목록에 안 보인다는 점만 다릅니다.

    작업 이름   PolicyEval
    부팅 30초 뒤 자동으로 켜짐
    죽으면 1분 뒤 다시 켬 (최대 999번)
    로그온하지 않아도 돎 (SYSTEM 계정)

  손으로 켜고 끄기:
    schtasks /Run /TN PolicyEval
    schtasks /End /TN PolicyEval


■ IIS 앞단

  모듈 두 개를 먼저 깝니다.

    URL Rewrite
      https://www.iis.net/downloads/microsoft/url-rewrite
    Application Request Routing
      https://www.iis.net/downloads/microsoft/application-request-routing

  ARR 은 설치한 뒤 한 번 켜야 합니다.

    IIS 관리자 → 서버 노드 → Application Request Routing Cache
              → Server Proxy Settings → Enable proxy 체크 → 적용

  그다음 사이트를 하나 만들고(실체 경로는 빈 폴더여도 됩니다)
  deploy_win\web.config 를 그 경로에 복사합니다. 규칙이 셋 들어 있습니다.

    BlockRecords   /records 와 /api/records 를 404 로 막습니다
    ForceHttps     평문을 https 로 보냅니다 — 주석으로 되어 있습니다
    ToUvicorn      나머지를 127.0.0.1:8000 으로 넘깁니다

  ForceHttps 는 인증서를 붙인 뒤에 주석을 푸십시오.
  인증서 없이 켜면 접속이 아예 안 됩니다.

  ※ 요청 제한은 기본으로 꺼져 있습니다. 리눅스판(nginx)에는 분당 30회
    제한이 켜져 있는데, IIS 에서 같은 일을 하려면 역할 기능을 하나 더
    깔아야 해서 기본은 꺼 두었습니다. 켜시려면:

      서버 관리자 → 역할 및 기능 추가 → 웹 서버(IIS)
        → 보안 → IP 및 도메인 제한

    그다음 web.config 의 dynamicIpSecurity 주석을 푸십시오.
    설치하지 않은 채 주석을 풀면 사이트 전체가 500 을 냅니다.
    (nginx 는 429 로 답하지만 IIS 는 403 밖에 고를 수 없습니다.
     403 이 갑자기 늘면 요청 제한 쪽을 먼저 의심하십시오.)

  인증서는 IIS 관리자에서 사이트 바인딩(https, 443)에 붙입니다.


■ HTTPS 는 선택이 아닙니다

  personal 판에서는 방문자가 화면에 자기 API 키를 붙여넣습니다.
  평문(http)으로 받으면 그 키가 도중에 드러납니다.
  인증서 없이 열지 마십시오.

  방문자의 키는 그 브라우저와 서버 메모리에만 있습니다.
  sessions.db 에도 로그에도 남지 않습니다.


■ 기록 화면(/records)은 밖에서 열리지 않습니다

  일부러 그렇게 두었습니다. sessions.db 에는 여러 사람의 문답이 함께
  쌓이므로, 접속한 사람이 남의 대화를 받아 갈 수 있으면 안 됩니다.
  초대 코드로 막는 것으로는 부족합니다(참여자 전원이 아는 값입니다).

  두 겹으로 막혀 있습니다.
    앱   프록시 머리표가 붙은 요청은 403
    IIS  /records 와 /api/records 는 404

  운영자는 서버에 원격 데스크톱으로 들어가 그 기계의 브라우저에서
    http://localhost:8000/records
  를 엽니다.

  ※ run_server.py 에 --proxy-headers 를 붙이지 마십시오. 그 옵션은
    X-Forwarded-For 를 client.host 로 바꿔치기하는데, 잠금장치가 보는
    것이 바로 그 값입니다. 붙이면 밖에서 온 요청이 내부 주소로
    위장해 통과합니다.


■ 판은 personal 입니다 — 밖에 열기 때문입니다

  mode.txt 한 줄이 판을 가릅니다. 이 zip 은 personal 로 되어 있습니다.

    personal     방문자가 각자 자기 Anthropic API 키를 화면에 넣습니다.
                 기관은 Claude 요금을 내지 않습니다.
    experiment   기관 키 하나로 전원이 씁니다.

  밖에 여신다면 personal 이어야 합니다. 초대 코드는 참여자 전원이 아는
  값이라 반드시 샙니다. experiment 로 열어 두면 코드가 새는 순간 남의
  실험이 기관 카드로 결제됩니다. 아이디어 1건에 300~600원입니다.

  ※ personal 판에서는 keys.local.bat 에 ANTHROPIC_API_KEY 를 넣지
    마십시오. 넣으면 방문자가 키를 안 넣어도 그 키로 돌아가 요금이
    기관에 붙습니다. 서버_1_설치.bat 이 이 경우를 발견하면 경고합니다.


■ 검증 통로는 네 개

  (1) 재정      data\fiscal.json         키 불필요 · 바로 작동
  (2) KDI 연구  data\kdi.sqlite          키 불필요 · 바로 작동
  (3) 국회 의안 open.assembly.go.kr      키 필요 (선택)
  (4) 해외사례  data\opsi_policies.db    키 불필요 · 바로 작동

  (3)의 키는 keys.local.bat 의 ASSEMBLY_KEY 에 넣거나, 방문자가 웹 첫
  화면에서 각자 넣습니다. 발급처는 열린국회정보(open.assembly.go.kr) —
  공공데이터포털(data.go.kr) 키와 다릅니다.

  통로 상태는 결과 화면 "커버리지"에 셋으로 구분되어 나옵니다.

    미실행     키·데이터가 없어 아예 돌리지 않음
    조회 실패  돌렸으나 오류로 결과를 못 받음
    N건        실제로 조회한 결과

  앞의 둘은 판정 근거로 쓰이지 않습니다. "0건"과 다르게 처리되며,
  이런 통로가 있으면 판정기가 확신도를 '상'으로 올리지 않습니다.

                   기관 SSO 를 한 겹 더 얹으셔야 합니다.

                   배포용 zip 에는 넣지 마십시오.

  갱신             새 zip 을 풀고 webapp\sessions.db 와 keys.local.bat 을
                   남겨 둔 채 나머지를 덮어쓴 뒤, 서버_1_설치.bat 을
                   다시 실행하고 작업을 재시작하십시오.
